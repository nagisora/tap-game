# tap-game 改善レビュー・パンチリスト（16ヶ月児向けタブレットおもちゃ）

対象プロダクト: `nagisora/tap-game`  
検証環境・対象: 16ヶ月児向け 約10インチ Android タブレット（Chrome PWA standalone + OS 画面ピン留め）  
本番デプロイ検証URL: `https://tap-game-pied.vercel.app/`  
レビュー方針: 開発者兼親（parent-developer）に向けた、事実と証拠に基づく具体的改善提案。プロダクトスコア外（SaaS化、スコア、メニュー、戻るボタン、フレームワーク等）の提案は含めず、純粋におもちゃとしての体験品質（因果関係の明瞭さ、誤操作防止、発達段階への適合）を精査する。

## 1. 改善パンチリスト（優先度順）

### P1 (Critical): ヤード（yard）画面における「あひる」と「ねこ」の接触・重なりとヒットボックス競合
- **何を見たか（現状）**:
  - `docs/qa/yard-landscape.png` および添付スクショ2（横向き）において、画面上方のあひる（duck）の下部が、中央のねこ（cat）の頭部に物理的にめり込んで重なっている（`duck: x=0.56, y=0.24`, `cat: x=0.42, y=0.48`）。
  - さらに `hitPadding`（短辺の6%、最小48px）で両者のバウンディングボックスが全方向に拡張されるため、ヒットボックスの重複面積が非常に広い。
  - 重複時は「中心間距離が近い方」を判定するが、あひるの足元やねこの頭部をタップした際、子ども自身が「あひるを触ったつもりなのにニャーと鳴る」、あるいはその逆が発生する。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 16ヶ月児にとって最も重要なのは「触ったものから音が鳴る」という1対1の確実な因果関係の学習である。見た目が融合していたり、境界付近で意図しない動物が鳴ると因果関係の把握が混乱する。
  - また、この時期の乳幼児の手指の運動精度は粗く、ピンポイントではなく手のひらや指先で対象の輪郭周辺を大まかに叩くため、境界重複は誤認識の主原因となる。
- **具体的修正案**:
  - `public/data/scenes.js` の `yard` シーンの配置座標を調整し、4体が均等に離れるようにする。
  - 例: あひるを右上寄り（`x: 0.62, y: 0.22`）、ねこを中央左下寄り（`x: 0.38, y: 0.52`）など、4体の expanded bbox の間に最低でも 24〜32px 以上のマージンが確保できるように座標を再配置する。

### P2 (High): 音声ラウドネスのバラつき（最弱 -24.1 LUFS 〜 最強 -12.1 LUFS、差 12 dB）
- **何を見たか（現状）**:
  - `public/assets/audio/*.mp3` 全12ファイルを `ffmpeg -filter_complex ebur128=peak=true` で実測したところ、仕様（PLAN.md: -16 LUFS 前後、True Peak ≤ -1.5 dBTP）に対して大きな乖離と個体差が存在する。
  - 実測値一覧:
    - `cow.mp3`: **-24.1 LUFS** (Peak -1.9 dBFS) ← **極端に小さい**
    - `pig.mp3`: **-22.9 LUFS** (Peak -1.9 dBFS) ← **極端に小さい**
    - `dolphin.mp3`: **-22.3 LUFS** (Peak -1.8 dBFS)
    - `chicken.mp3`: **-19.5 LUFS** (Peak -2.3 dBFS)
    - `dog.mp3`: **-19.0 LUFS** (Peak -2.0 dBFS)
    - `frog.mp3`: -16.4 LUFS (Peak -1.5 dBFS)
    - `seagull.mp3`: -16.1 LUFS (Peak -2.4 dBFS)
    - `sheep.mp3`: -15.8 LUFS (Peak -2.0 dBFS)
    - `duck.mp3`: -15.8 LUFS (Peak -2.0 dBFS)
    - `penguin.mp3`: -15.4 LUFS (Peak -2.2 dBFS)
    - `cat.mp3`: **-13.2 LUFS** (Peak -1.9 dBFS) ← **大きい**
    - `seal.mp3`: **-12.1 LUFS** (Peak -1.9 dBFS) ← **極端に大きい（目標より約4dB大）**
  - 最も静かな `cow`（-24.1 LUFS）と最も大きな `seal`（-12.1 LUFS）の間に **12.0 LUFS（約12dB、音圧比で約4倍）** もの差がある。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 親が `cow` や `pig` の鳴き声に合わせてタブレットのハードウェア音量を上げると、次に `cat` や `seal` をタップした瞬間に爆音で鳴り響き、子どもが恐怖で泣き出したり、びっくりしてタブレットを投げ落とす危険がある。
  - 逆に `seal` に合わせて音量を下げると、`cow` や `pig` がほとんど聞こえず「無反応（ミス）」と誤認される。
- **具体的修正案**:
  - 全音声を再度 ffmpeg の `loudnorm` または SoX 等で目標値 `-16.0 LUFS`（True Peak `-1.5 dBTP`）に揃えて再エンコードする。
  - 実行例:
    ```bash
    ffmpeg -i input.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=7 -ar 44100 -b:a 96k output.mp3
    ```

### P3 (High): 縦向き（portrait）における全シーンの動物密集と画面下部への偏り
- **何を見たか（現状）**:
  - 添付画像4〜6（`farm-portrait.png`, `yard-portrait.png`, `sea-portrait.png`）を精査すると、すべてのシーンにおいて4体の動物が画面の中央〜下部、および左半分に極度に密集している。
  - 特に `farm-portrait` ではひつじが最下部に追いやられ、`yard-portrait` ではいぬとねこ、あひるが垂直方向に数珠つなぎになり、`sea-portrait` ではイルカの尾びれとあざらしの前足が接触寸前となっている。
  - 原因は CSS と座標定義にある。動物のサイズが `width: min(28vmin, 34vw)` であり、縦向きでは `vmin` が画面幅（短い辺）基準となるためサイズは維持されるが、`scenes.js` に定義された固定比率 `(x, y)` が横向き（16:10 / 16:9）を主眼にチューニングされているため、縦長アスペクト比（10:16等）になると Y 方向に詰まり、X 方向にも右側の ▶ ボタン（幅 176px）を避けるために左側に圧縮されてしまう。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 16ヶ月児はタブレットを両手で持ったり床に置いて遊ぶ際、縦向き（portrait）に置くことも非常に多い（親が横向きで渡しても子どもが回転させる）。
  - 縦向きで動物が密集すると、小さな手や指でも隣の動物を誤タップしやすくなり、狙った動物と違う声が鳴るストレスが生じる。
- **具体的修正案**:
  - 選択肢A（CSS/メディアクエリ導入）: `@media (orientation: portrait)` を使用するか、JavaScript の `renderScene()` で `isPortrait` を判定し、縦向き用の `(x, y)` 座標テーブル（または縦並びレイアウト）に切り替える。
  - 選択肢B（座標の汎用正規化）: 横向き・縦向きのどちらでも破綻しないよう、画面の上下左右の余白を均等に使う座標配置（例: 2×2 の四隅配置に近い配置）に再調整する。

### P4 (Medium): ヤード画面における「かえる」と背景色のコントラスト不足
- **何を見たか（現状）**:
  - `yard` シーンの背景色は黄緑色 `#C5E478`、かえる（frog）の体色も同系統の緑色（`#71B33C` 付近）である。
  - スクリーンショット（添付2、5）で見ると、黒のアウトラインはあるものの、他の動物（茶の犬、オレンジの猫、黄色のあひる）に比べて明度・色相の分離が弱く、背景と同化して見える。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 16ヶ月児の視覚認識力は発達途上であり、背景と前景のコントラストが低い図形は見落としやすい。「そこに動物がいる」と直感的に気づけない可能性がある。
- **具体的修正案**:
  - かえるのイラストの緑色を少し鮮やかな青緑や深いエメラルドグリーンにするか、腹部のクリーム色領域を広く見せる。
  - または、ヤードの背景色を芝生感のある別のトーン（少し彩度を落とした温かみのあるベージュグリーンや、青空寄りの二色ではなく単色でも差別化できる色調）に調整する。

### P5 (Medium): シーン固有のアイデンティティ（背景）の抽象度過剰と「浮遊感」
- **何を見たか（現状）**:
  - `farm` は `#7CB342`（緑一色）、`yard` は `#C5E478`（薄黄緑一色）、`sea` は `#4FC3F7`（水色一色）。
  - 3シーンとも完全な単色ベタ塗りであり、地面・水面・水平線などの環境境界が一切存在しない。
  - そのため、海シーンではかもめ・ペンギン・あざらし・イルカがすべて「水色の空間」に同じように浮いており、陸上動物（うし、ぶた、いぬ、ねこ）も空中浮遊しているように見える。
  - `farm` と `yard` はどちらも「緑系の単色」であるため、▶ を押して切り替わったときに「別のシーンに来た」という場面転換の実感が薄い。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 16ヶ月児でも「ワンワンのお庭」と「お水・ジャブジャブ（海）」の区別は絵本等でつき始めている。しかし現状の `farm` と `yard` は同系色の明度違いに過ぎず、シーンが切り替わったのかどうかの認識が遅れる。
  - また、海シーンでイルカが空を飛んでいるのか、ペンギンが水中にいるのかが視覚的に伝わりにくい。
- **具体的修正案**:
  - PLAN.md の「写真・繁雑な風景は禁止」「Webフォントや余計なUIなし」の制約を守りつつ、ごくシンプルな「地面/水平線の色分け」（ベタ塗り2分割、または下部1/3にシンプルな地面色・波ラインの帯）を CSS または SVG/Canvas の背景として導入する。
  - これにより動物の「足元」が安定し、`farm`（土と草の丘）、`yard`（庭先）、`sea`（空と海）のシーン区別が一瞬で直感できるようになる。

### P6 (Medium): ▶（次へ）ボタンのコントラストとアフォーダンス（ヤード画面）
- **何を見たか（現状）**:
  - ▶ ボタンの三角は `#fff8e7`（クリーム色）、背景には CSS で `filter: drop-shadow(0 3px 0 #2a2218)` が適用されている。
  - しかし、`yard` の背景色（`#C5E478`）は明度が高く、クリーム色との明度差が小さいため、添付2・5で見ると三角の存在感がかなり薄くなっている。
  - また、三角図形単体で置かれているため、16ヶ月児が「これを押すと何かが変わる」というインタラクティブなボタン（アフォーダンス）として認識しづらい。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - 飽きたときに自力でシーンを切り替えて遊び続けられることが自立プレイの鍵だが、▶ の視認性が低いと親が押してあげる必要が生じてしまう。
- **具体的修正案**:
  - 三角の背景に、薄い円形のベース（半透明の白、または濃い色の円形プレート）を敷くか、三角自体のドロップシャドウ・アウトラインを太くして、どの背景色（緑・黄緑・水色）の上でもくっきり浮き立つようにする（PLAN.md 3.5「白三角 + 暗い円、または単色の大きな三角」に準拠）。

### P7 (Low): アプリ起動時および初回アンロック時の無音リスク（ロード完了待ちの挙動）
- **何を見たか（現状）**:
  - `app.js` では `onPointerDown` のハンドラ内で `await ensureAudio()` と `await loadBuffers()` を呼んでいる。
  - 初回起動時、親が画面を開いてすぐに子どもに渡した場合、バックグラウンドでの `loadBuffers()`（12ファイルの fetch + decode）が完了する前に子どもが動物をタップすると、Promise が解決するまで音が鳴るのに数十〜数百ミリ秒のラグが生じる可能性がある。
  - また、もし初回オフライン時（SW のプリキャッシュ前）に開かれた場合、デコードに失敗すると `catch` で握りつぶされ「完全に無音（ミス相当）」になる。
- **16ヶ月児（~10インチAndroidタブレット）にとってなぜ重大か**:
  - タップから発声までに 100ms 以上の遅延があると、「自分が触ったから鳴った」という即時因果フィードバックが成立しなくなる。
- **具体的修正案**:
  - 現状でも `PARENT.md` に「自分で1回タップして鳴ることを確認（初回キャッシュ）」と書かれており親の手順でカバーされているが、アプリ側でも `DOMContentLoaded` 直後に全アセットの decodeAudioData を即座に開始し、キャッシュ完了を早める（親が渡す前の待機時間を最小化する）。

## 2. 既に良好に機能している点（Already Fine）

コードベースおよび実機スクリーンショットの検証により、以下の設計と実装は 16ヶ月児向けのおもちゃとして極めて高い完成度に達している。**変更する必要はない**。

1. **軸平行バウンディングボックスの拡張（Hit Box Inflation）と「ミス時は完全無音」の徹底**:
   - `hitPadding = max(48, 0.06 * shortViewport)` により、小さな子どものアバウトなタッチでも確実にヒットする。
   - 空白地帯をタップした際に「ブブー」などの失敗音や振動を出さず、完全な無処理（no-op）を貫いている点は、幼児の発達心理上極めて優れている。
2. **排他再生（Cut previous, play new）と Web Audio API による即時性**:
   - `AudioBufferSourceNode` を使い、連打された瞬間に前の音を `stopCurrent()` して最新の音を再生する実装は、幼児の連打によるカオス音や不快な重なりを完璧に防止している。
3. **過剰な演出の排除（Wordless, No-clutter UI）**:
   - スコア、タイマー、星、文字、設定アイコン、戻るボタン等のUIノイズが一切なく、画面上に「動物4体」と「▶」しか存在しない。16ヶ月児の視覚的集中力を妨げない。
4. **ヒット時のリアクション（180ms スケールアニメーション）**:
   - タップ時に `animal-pop`（1.0 → 1.08 → 1.0）のアニメーションが適用され、自分が触った実感を視覚的にも即座に得られる。
5. **堅牢なジェスチャ・スクロール抑制**:
   - `touch-action: none`, `user-select: none`, `overscroll-behavior: none`, `contextmenu` 抑止、`touchmove` 抑止など、ブラウザ特有の誤動作（ピンチズーム、テキスト選択、プル・トゥ・リフレッシュ）が徹底して潰されている。
6. **WebP q90 による高画質かつ超軽量なアセット設計**:
   - 動物イラストが 1体あたり 30〜50KB 程度に収まっており、Service Worker による全アセットの初回一括プリキャッシュ（`cache.addAll`）が数秒以内に完了する。オフライン PWA としての信頼性が極めて高い。

## 3. ドキュメントと実装の齟齬（Doc-Only Mismatches）

実装コードと仕様書（PLAN.md / SUMMARY.md / LICENSES.md）を突き合わせた結果、以下の記述の不一致が確認された。これらは動作上のバグではないが、ドキュメント側の更新が推奨される。

1. **ホスティング環境の記載（Cloudflare Pages vs Vercel）**:
   - `PLAN.md`（0節、8.3節）、`SUMMARY.md`、`README.md` では一貫して「Cloudflare Pages（Direct Upload）」「wrangler pages deploy」と規定されている。
   - しかし実際の実稼働 URL は `https://tap-game-pied.vercel.app/` であり、Vercel 上にデプロイされている。親向けドキュメントや運用手順に混乱が生じないよう、Vercel 運用に更新するか、Cloudflare Pages の位置づけを整理すべきである。
2. **画像フォーマットの記述（SVG vs WebP）**:
   - `PLAN.md` 2節（データ形）では `art: "assets/art/farm/cow.svg"` と SVG 前提のサンプルコードが記載されている。
   - 実際の実装（`scenes.js`）および `LICENSES.md` では、最適化検証を経て `assets/art/*/*.webp` が正式採用されている。`PLAN.md` の記述を現状の WebP に整合させるのが望ましい。
3. **PWA アイコンの maskable 指定（manifest.webmanifest）**:
   - `PLAN.md` 5.4節では「192px と 512px の PNG。`purpose: "any maskable"` 用にセーフゾーンを取る」と記載されている。
   - 実際の `manifest.webmanifest` では、192px は `"purpose": "any"`、512px のみが `"purpose": "any maskable"` となっている。Android の一部ランチャーでは 192px 側にも maskable が求められる場合があるため、ドキュメントの記述または manifest の設定を統一するとよい。
4. **Service Worker キャッシュ名の命名規則**:
   - `PLAN.md` 8.1節では `CACHE = 'animal-tap-v1'` と記載されているが、`sw.js` の実際の実装は `CACHE = "tap-game-v5"` となっている（クリーンアップロジックでは両方のプレフィックスに対応している）。
